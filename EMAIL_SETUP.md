# Email Setup

The application sends mail through the institution's authenticated SMTP service in production. For development, use the local Mailpit mock server below; it captures messages and does not deliver them to real inboxes. Keep production SMTP credentials in the web server's environment configuration and out of this repository.

The local-only `.env.local` file is automatically loaded by the shared mailer for settings not already supplied by the server process. It is excluded by `.gitignore`. This lets existing local PHP servers use Mailpit without needing to be restarted with special environment variables. Explicit process/server environment variables always take precedence.

## Install

Install PHP Composer, open a terminal in this directory, then run:

```powershell
composer install
```

This creates `vendor/autoload.php`, which the shared mailer loads when sending.

## Local Mock SMTP

Mailpit is installed per-user under `%LOCALAPPDATA%\Mailpit`. The project launcher expects `mailpit.exe` at that location and keeps both listeners bound to `127.0.0.1` only.

To install or update the Windows x64 binary, download the official [Mailpit v1.31.4 release](https://github.com/axllent/mailpit/releases/download/v1.31.4/mailpit-windows-amd64.zip), verify its published SHA-256, then extract `mailpit.exe` to `%LOCALAPPDATA%\Mailpit`:

```powershell
$archive = Join-Path $env:TEMP 'mailpit-windows-amd64.zip'
$installDir = Join-Path $env:LOCALAPPDATA 'Mailpit'
Invoke-WebRequest 'https://github.com/axllent/mailpit/releases/download/v1.31.4/mailpit-windows-amd64.zip' -OutFile $archive
if ((Get-FileHash $archive -Algorithm SHA256).Hash.ToLowerInvariant() -ne '0dd6ec909a6f5b2b66682b22d82abce97ab793e30766bf2f642b691e70a4a16b') { throw 'Mailpit checksum mismatch.' }
New-Item -ItemType Directory $installDir -Force | Out-Null
Expand-Archive $archive $installDir -Force
Remove-Item $archive
```

From this project folder, run:

```powershell
.\start-local-mail.ps1
```

This starts Mailpit's SMTP listener at `127.0.0.1:1025`, its inbox UI at `http://127.0.0.1:8025`, and a portal server at `http://127.0.0.1:8769/grading_app/grading_app/login.php`. The `.env.local` profile also lets an already-running local PHP server use Mailpit. Use the inbox to inspect registration codes, login alerts, and announcements generated by the app.

## Configure

Ask MIS for the approved SMTP host, port, encryption, username, password, and sender address. Configure these environment variables for the PHP web server process:

- `SMTP_HOST`
- `SMTP_PORT` (usually `587` for TLS or `465` for SSL)
- `SMTP_ENCRYPTION` (`tls` or `ssl`; `none` only for the loopback mock)
- `SMTP_AUTH` (`true` by default; set to `false` only for a local mock server)
- `SMTP_USERNAME`
- `SMTP_PASSWORD`
- `SMTP_FROM_EMAIL`
- `SMTP_FROM_NAME` (optional; defaults to `Academic Portal`)

For a local PHP development server, set the variables in the same PowerShell session before starting PHP, for example:

```powershell
$env:SMTP_HOST = '<host supplied by MIS>'
$env:SMTP_PORT = '587'
$env:SMTP_ENCRYPTION = 'tls'
$env:SMTP_AUTH = 'true'
$env:SMTP_USERNAME = '<mailbox username>'
$env:SMTP_PASSWORD = '<mailbox password>'
$env:SMTP_FROM_EMAIL = '<approved sender address>'
$env:SMTP_FROM_NAME = 'Academic Portal'
php -S localhost:8000
```

For Apache, IIS, or production hosting, configure the variables in the server/service environment or hosting control panel and restart the web server. Do not use the local PowerShell example for a separately running Apache service.

The local Mailpit profile deliberately uses no SMTP authentication or transport encryption because it is loopback-only and captures mail instead of relaying it. The mailer rejects unauthenticated SMTP unless the configured host is `localhost`, `127.0.0.1`, or `::1`. Do not point production traffic at Mailpit, expose its ports publicly, or use `SMTP_AUTH=false` with an external mail server.

## Delivery behavior

Email failures are written to the PHP error log and do not undo an in-app notification or a successfully submitted request. Registration verification is different: registration will not proceed to the code-entry step unless the verification email is accepted for sending. SMTP acceptance does not guarantee inbox delivery, so test with MIS-approved addresses and check spam filtering and mail logs.
